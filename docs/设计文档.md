# 小荷 MedRAG 设计文档

## 1. 架构概览

```text
med-rag-data（只读）
        │
        ▼
validate → parse → normalize → chunk → SQLite/FTS5/graph
                                              │
用户问题 → 术语归一化 → BM25/FAQ/Graph/药物/检验召回 → RRF 去重
                                              │
                         LangGraph retrieve → compose → audit → finalize
                                              │
                         FastAPI JSON ← React/Vite 工作台 ← Caddy HTTPS
```

## 2. 目录职责

- `src/medrag/ingestion.py`：Markdown、PDF、结构化 JSON 解析，来源清单和父子 Chunk。
- `src/medrag/normalization.py`：别名、缩写、药品和疾病术语标准化，实体识别和 jieba 分词。
- `src/medrag/storage.py`：SQLite Schema、FTS5、结构化表、图谱关系、会话记录和 manifest。
- `src/medrag/retrieval.py`：多路召回、加权 RRF、来源去重和直接证据优先级。
- `src/medrag/pipeline.py`：LangGraph 状态图，串联检索、模板生成、安全审核和响应封装。
- `src/medrag/safety.py`：急症、严重相互作用、无证据和剂量输出的 fail-closed 规则。
- `src/medrag/app.py`：健康检查、问答、会话、指标、相互作用和文档预览 API。
- `frontend/src/`：ChatGPT 风格侧栏、固定底部输入框、回答区、引用区、知识库和评估页。

## 3. 数据模型

### ChunkRecord

每个 Chunk 都包含 `chunk_id`、`source_id`、来源名称、文档类型、章节、页码、证据等级、可信度和父 Chunk ID。回答引用直接由 Chunk 生成，避免只保留自然语言来源名而无法回溯。

### QueryResponse

响应包含 `answer`、`citations`、`risk_level`、`safety_status`、`warnings`、`confidence`、`follow_up`、标准化查询、实体和检索 trace，前端可以同时展示答案和证据链。

## 4. 检索策略

1. 查询标准化并抽取药物、疾病、检验和症状实体。
2. SQLite FTS5 召回关键词候选，未命中时使用字符串计分回退。
3. FAQ 独立检索；两种药物同时出现时优先查相互作用表。
4. 命中检验项目时查结构化检验值；命中图谱实体时查关系表。
5. 按路由权重、证据可信度和路由排名计算 RRF，按 `source_id` 去重。
6. 相互作用和检验结果直接证据置于首位，以保证关键回答的引用准确性。

## 5. 安全设计

安全审核发生在生成之后、响应之前。检测到急症时提升为 `critical/urgent_referral`；检测到严重相互作用时为 `high/high_risk_review`；没有可验证医学实体或证据时清空引用并返回 `blocked_no_evidence`。所有正常回答都附加医疗免责声明。

## 6. 技术取舍

当前版本优先保证离线、可重复和低成本运行，因此使用 SQLite FTS5 与内存/SQLite 图谱适配器，不强制依赖外部模型服务。Embedding、Reranker、Neo4j 和 LLM 已保留增强边界，后续可以替换召回和生成实现而不改变 API 契约。
