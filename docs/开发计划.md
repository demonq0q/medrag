# 小荷 MedRAG 开发计划与实施状态

## 1. 项目目标

小荷是一个面向基层医生、药师和患者的医学知识辅助问答系统。系统只基于版本化知识库生成回答，并对药物相互作用、急症、剂量和无证据问题进行保守审核。

原始数据目录 `med-rag-data/` 保持只读，所有 SQLite 数据库、清单和评估报告写入 `artifacts/`。

## 2. 分阶段计划

| 阶段 | 目标 | 状态 |
| --- | --- | --- |
| Phase 1 | 数据清点、哈希、来源 ID、Markdown/JSON/PDF 解析、医学术语归一化、Chunk 构建 | 已完成 |
| Phase 2 | SQLite FTS5 检索、FAQ/结构化检索、知识图谱关系和可重复构建 | 已完成 |
| Phase 3 | LangGraph 编排、BM25 风格关键词融合、GraphRAG、RRF、来源去重和引用 | 已完成 |

| Phase 5 | 回归评估、交付文档、外网验证和 Git 发布 | 进行中/本轮完成本地交付，GitHub 推送待凭据 |

## 3. 当前实现范围

- 读取 78 个有效源文件：65 个 Markdown、4 个 PDF、7 个 JSON；忽略备份文件和采集脚本运行日志。
- 构建 1,700 个子 Chunk、160 个父 Chunk，并保留 PDF 页码和章节信息。
- 结构化导入 30 条 FAQ、55 条药物相互作用、45 条检验参考值、115 个图谱实体和 103 条图谱关系。
- 对 `扑热息痛`、英文药名、常见疾病别名执行最长词优先归一化。
- 使用 SQLite FTS5、FAQ、相互作用、检验值和图谱关系五路召回，并用加权 RRF 融合。
- 使用 LangGraph 固化 `retrieve → compose → audit → finalize` 流程；没有模型密钥时使用可审计模板生成器。
- 使用规则审核急症、严重相互作用、无证据问题和无来源剂量，并统一添加免责声明。

## 4. 后续增强路线

1. 接入可配置 Embedding Provider 与 Chroma，补充 Recall@K、MRR、NDCG 对比实验。
2. 接入 Cross-Encoder Reranker，并增加候选证据压缩和冲突检测。
3. 将 SQLite 图谱适配器扩展为 Neo4j 后端，支持 1～2 跳 Cypher 查询。
4. 接入经过审核的 OpenAI-compatible LLM Provider，保留模板模式作为离线回退。
5. 将评估集从当前 50 条扩充至 150 条以上，并增加 20 条以上安全专项用例。

## 5. 验收门槛

- 每个答案引用 ID 必须能映射到真实 Chunk。
- 高风险问题不得输出无引用药物剂量。
- 未知药物、未知剂量和无证据问题必须保守拒答。
- Docker 启动后 `/health` 为 `ready`，外网 HTTPS 页面和 API 均可用。
- Python 单元/集成测试、Ruff 检查和前端生产构建全部通过。
